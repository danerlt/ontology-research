## 英文原文短摘录（每个来源不超过 25 词）

> “In snapshot isolation mode, the platform rejects the edits to avoid overwriting the other action's changes.”

## 摘录译文

快照隔离模式下，平台会拒绝发生冲突的编辑，避免覆盖另一项动作所做的修改。

## 中文要点

- 两个动作并发修改同一对象时，即使编辑的是不同属性，快照隔离也会发生对象级冲突。对象类型的数据源更新冲突检查范围可能覆盖整个类型，即使更新行与当前动作修改对象无关也可能失败；对象数据库维护也会产生短暂冲突。
- 可配置瞬时错误重试：默认只重试无外部调用的动作，也可重试所有动作或关闭重试。平台把 OSDK 访问（包括只读请求）算作外部调用，因此 TypeScript v2 与 Python 中通过 OSDK 的函数型动作默认不自动重试。
- 若选择重试所有动作，必须评估 Webhook 等副作用是否幂等；重复调用可能产生重复编辑。启用后平台最多尝试五次，盲目在 API/Automate 再叠加重试会增加延迟和负载。
- 排查可通过对象编辑历史定位并发写入，但它只记录启用后的用户编辑，不包含底层数据源更新。也可串行化同对象动作、合并共享写集的动作，或在理解语义后改用 Read committed。

## 术语对照

| 英文术语 | 中文译法 | 本页语境 |
|---|---|---|
| conflict error | 冲突错误 | 并发或数据源版本变化使动作提交被拒。 |
| transient error retry | 瞬时错误重试 | 对短暂冲突自动重新运行动作。 |
| idempotent | 幂等 | 重复执行不会产生重复副作用或额外更改。 |
| ObjectVersionChanged | 对象版本已变更 | 文档列出的动作冲突错误之一。 |

## 疑问与待验证项

- 所有动作最多重试五次的表述需结合当前环境能力核验；API 客户端自行重试可能放大副作用，必须与平台 retry mode 一起设计。
- 使用读已提交解决冲突可能引入覆盖写和读视图变化，不应只为降低失败率而切换隔离级别。

## 复刻启示

- 为每个提交保存对象版本、写集、数据源版本与冲突原因；以对象级并发控制拒绝覆盖，并提供可定位到对象/属性/调用来源的 409 冲突详情。
- 自动重试先检查动作是否包含非幂等外呼；外部副作用和本体事务要使用 outbox/idempotency key 或补偿机制，不能盲目重复执行。
- 同对象动作可用队列串行化；对数据源刷新冲突显示类型级影响范围和建议等待窗口。编辑历史与数据源重建事件应分别记录。
