## 中文要点

- 在对象引用参数的下拉校验中使用静态属性值，会让可查看操作类型但无权查看目标对象的用户推知该属性值组合。
- 改用对象属性或另一个参数来筛选对象集，可减少直接把敏感静态常量写进操作定义的风险；对象可见性仍由对象权限规则控制。
- 表单 UI 不直接显示过滤值，但浏览器网络请求中的对象集 RID/条件可能暴露筛选内容，不能只凭 UI 隐藏判断安全。
- 官方中文译文标注为未经验证的机器翻译；安全解释以英文版的技术细节为准。

## 疑问与待验证项

- 文档建议的替代方案仍要结合属性级权限、对象过滤和 API 响应检查，本文不承诺所有参数化方式都能隐藏所有元数据。
- 是否能在日志、浏览器开发者工具或其它客户端观察到筛选条件，应在本系统的威胁模型中纳入验证。

## 复刻启示

- 任何动态下拉过滤都应执行服务端授权过滤，并避免向未授权用户返回可推断敏感业务值的筛选条件。
- 安全评审检查需覆盖 UI、网络负载、RID、错误消息和可见元数据，不仅检查页面渲染结果。
