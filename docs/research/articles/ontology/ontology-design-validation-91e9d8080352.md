## 英文原文短摘录（每个来源不超过 25 词）

> “Time to answer is a design signal.”

## 摘录译文

回答问题所需的时间是设计质量信号。

## 中文要点

- 结构检查可验证类型语义、链接基数和接口关系，却不能证明用户能从业务问题找到起点、沿链接完成调查。
- 问题应来自组织重复且后果显著的日常决策；设计多步骤路径，从识别情况、追溯影响因素到评估风险与可干预点。
- 测试应记录正确率、完成时间、搜索词、尝试的对象/链接、犹豫和求助；导出数据或手工 join 往往指出模型缺少业务关系。
- 人与 Agent 的表现需要对照：AI 成功而人困难时检查名称/别名/视觉层级；人成功而 AI 困难时检查未显式表达的业务逻辑。验证应持续进行并沉淀为评估集。

## 术语对照

| 英文术语 | 中文译法 | 本页语境 |
|---|---|---|
| task-based validation | 任务式验证 | 用真实业务问题检验模型是否可被实际使用。 |
| analytical drill | 分析演练 | 让参与者在通用分析工具中现场完成未知问题。 |
| time to answer | 回答耗时 | 衡量本体路径是否自然、易发现的一项指标。 |

## 疑问与待验证项

- - 演练评价应区分模型、底层数据、权限、应用封装和用户培训问题，避免把每次失败都归因到 Ontology。
- - Agent 评测权限需与人类参与者的可见范围一致，同时单独标注工具与模型上下文。

## 复刻启示

- - 在画布内把业务问题样例关联到对象类型、关系路径、属性计算和行动；缺链、模糊语义及重复模型会直接显示为验证缺口。
- - 建立可复跑的评估用例并记录答案、推理/导航路径、耗时、错误节点与人工介入；对人和 Agent 分别评估、对比趋势。
