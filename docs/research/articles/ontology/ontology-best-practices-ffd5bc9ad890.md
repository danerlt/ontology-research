## 英文原文短摘录（每个来源不超过 25 词）

> “Model reality, not systems.”

## 摘录译文

建模现实世界，而不是建模各个系统。

## 中文要点

- 对象类型应表达现实领域实体，而不是源系统表或部门视图；链接表达真实关系，而不是数据库 join/key 结构。
- 属性要经过业务筛选；跨团队协作以减少重复建模；单个对象类型聚焦一个实体，重复的共同特征可抽象为 interfaces。
- Action types 适合需要人或 Agent 决策的操作，pipeline 适合自动化变换；对象、属性和链接要有业务文档。
- 设计须围绕真实业务任务验证：确认人和 Agent 能理解并使用模型回答问题、支持重要决策。

## 疑问与待验证项

- - 原则的优先级说明设计冲突时应优先保护真实领域语义，但实际拆分颗粒度仍需业务专家与消费者共同判断。
- - 设计验证页的具体评估流程需结合其单独文档；这页强调了任务测试而非只检查 schema。

## 复刻启示

- - 画布节点默认用业务名称和实体语义呈现，可在属性检查器中显示映射到的源系统字段，避免把物理数据表误作领域模型。
- - 每个类型/关系保存业务定义、owner、关联业务问题和来源映射；新增资源进入验证清单，检查语义、重复、可访问性和 Agent 可导航性。
