# 英文原文短摘录（每个来源不超过 25 词）

> “To access time series properties in a workspace, follow the preceding steps to create, publish, and import an Ontology SDK.”

## 摘录译文

若要在工作区访问时间序列属性，先按前述流程创建、发布并导入 Ontology SDK。

## 中文要点

- 每个 Code Workspace 配置一个 OSDK，但可以生成多个 SDK 版本；选择本体中的对象、链接和 Action，生成的 SDK 才能在工作区代码中使用。
- 选择 Action 时，相关对象类型会自动加入；对象类型的数据源如果尚未进入工作区项目范围，界面会提示自动导入。
- 切换 Ontology 会清空已选对象、Action 和链接，再生成新版本；只有状态为 Published 的版本可供代码安装。
- Python 示例涵盖按主键读取、遍历、筛选、聚合和先校验后执行 Action；时间序列通过 FoundryTS 处理，R 可经 reticulate 调用 Python OSDK。
- Restricted View-backed 实体和 Query Functions 当前不受 Code Workspaces 支持。

## 术语对照

| 英文术语 | 中文译法 | 本页语境 |
|---|---|---|
| Data entities | 数据实体 | SDK 生成时可选的本体类型资源 |
| SDK generation | SDK 生成 | 创建并检查 OSDK 版本的工作区面板 |
| Published version | 已发布版本 | 可被代码安装和使用的 SDK 版本 |
| FoundryTS | Foundry 时间序列库 | 在工作区中处理本体时间序列属性 |

## 疑问与待验证项

- Restricted View-backed 类型与 Query Functions 的支持范围可能随版本变化，部署时需按当前工作区能力核验。
- Action 校验与最终提交是两个请求；校验后对象状态可能变化，应确认冲突处理和重试规则。

## 复刻启示

- SDK 生成物绑定 schema 版本，只有已发布版本进入消费者依赖；切换本体时显示影响并清除旧选择。
- 项目设置呈现“本体类型→数据源→代码依赖”，发布时检查缺失对象类型与数据源。
