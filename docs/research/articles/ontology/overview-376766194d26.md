## 英文原文短摘录（不超过 25 词）

> “By treating Foundry as your backend, you can leverage the Ontology's robust ability to perform high-scale queries and Foundry edits alongside granular governance controls”

## 摘录译文

将 Foundry 作为后端，可利用本体执行大规模查询和 Foundry 编辑，并配合细粒度治理控制。

## 中文要点

- React 应用由 Developer Console 建立，前端可完全自定义；Foundry 侧承担本体查询、编辑及相关治理控制。
- `@osdk/react` 提供带类型的 hooks、共享缓存、Action/Function 调用和数据驱动界面；`@osdk/react-components` 建立在前者之上，提供预制的本体感知 UI 元素。
- OSDK 不局限于 TypeScript：文档同时列出 Python 的 Pip/Conda、Java 的 Maven，以及其他语言可用的 OpenAPI 规范。
- 配套示例从待办应用入门，进一步展示 AIP Logic 调用和把 Web 托管 React 应用嵌入 Workshop 的双向状态交互。

## 疑问与待验证项

- 此概览没有规定缓存失效、乐观更新或组件设计系统的细节；需分别研读 React 库和组件库文档。
- “高规模查询”和治理能力是平台定位，本文未提供量化吞吐、延迟或具体权限判定算法。
- 文档同时列出多语言 SDK，但各语言对本体能力的覆盖并不必然相同，需以各 SDK 功能矩阵为准。

## 复刻启示

- 把生成 SDK 与自定义 UI 分层：SDK 描述有类型的对象、链接、查询和操作；React 层封装缓存、加载状态及本体组件。
- 复刻需提供领域 API 与权限治理，而不是将本体数据直接塞进前端状态；所有写入通过受控 Action 或提案入口。
- 多语言接入应共享统一的 schema/权限契约，并展示各 SDK 的能力差异。
